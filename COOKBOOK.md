# Total.js 5 cookbook — building apps

Practical recipes, conventions and lessons learned for building applications on **Total.js 5**. It covers both kinds of projects:

- **server-rendered websites** — a content catalog with search, detail pages, pagination and thorough SEO, with no database and no frontend framework,
- **API backends** — plugins, actions, authorization, PostgreSQL, uploads, WebSockets and background jobs.

The cookbook is project-independent and meant as the single reference for new projects: an app should be buildable from this file alone. The examples use generic names ("items", "orders"); replace them with your own domain. Copy the **mechanism**, never another product's tables or schema names.

**How to read it:** sections 1–6 are the rules that apply to every file. Sections 7–18 are the backend. Sections 19–23 are the website layer. Sections 24–28 are quality: performance, security, anti-patterns, gotchas and a checklist. When two recipes seem to compete, the tables in [section 1](#1-architecture-and-principles) ("Where each kind of code goes") and [section 26](#26-anti-patterns) decide.

## 1. Architecture and principles

Total.js is not Express and not Nest. Do not redesign it around routers, DI containers or `require()` graphs. **If a pattern would make sense in Nest or Fastify, it is probably the wrong Total.js pattern.**

The running application is a **single global framework instance**. Files are auto-loaded by directory. Application code shares behavior through globals, not imports.

### The seven rules

1. **Globals, not imports.** `FUNC`, `MAIN`, `MODS`, `CONF`, `DATA`, `PATH`… already exist ([section 6](#6-globals)). There is no service locator to invent — they are the locator.
2. **Directories, not registration.** Put a file in the right directory and the framework loads it ([section 2](#2-project-structure)).
3. **Actions own the domain.** Business rules live in `NEWACTION` / `NEWSCHEMA` ([section 8](#8-actions-newaction-and-newschema)). Controllers own HTTP, files and sockets only ([section 9](#9-controllers-and-routing)).
4. **A feature is a plugin.** `plugins/<feature>/index.js` + `schemas/` ([section 10](#10-plugins)).
5. **One of each.** One `AUTH()` delegate, one `CORS()` call, one API gateway (`POST /api/`), one response envelope (`$.success()`).
6. **Code is written for a person.** Someone who opens the file in a year must understand it without running it: plain names, short functions and a comment wherever the reason is not obvious from the code ([section 5](#5-coding-style), "Comments").
7. **Code is written to be copied.** An action, a module or a plugin should work in the next project after copying its file or folder: what differs between projects is in `config`, and the file says at its top what it needs ([section 5](#5-coding-style), "Reusable code").

### `require()` policy

`require()` is exceptional. Legitimate:

```js
require('total5');                                                   // index.js only
require('querybuilderpg').init('', CONF.database, 1, ERROR('DB'));   // definitions/db.js
const { S3Client } = require('@aws-sdk/client-s3');                  // a real external SDK, inside a module
```

Not legitimate inside controllers, schemas, actions, definitions or modules:

```js
// WRONG — internal sharing and Node built-ins
const storage = require('../modules/storage');
const helper = require('./lib/db');
const Path = require('path');
const Fs = require('fs');
const https = require('https');
```

Use instead:

```js
MODS.storage.putFile(...);
FUNC.hash_password(password);
PATH.join(PATH.public(), 'uploads');
PATH.fs.readFileSync(filename);
RESTBuilder.POST(url, payload).promise($);
```

CLI scripts, one-off migrations and tests that run *outside* `Total.run()` (`node scripts/migrate.js`) may `require()` Node built-ins and `pg`. Application runtime code must not.

### Where each kind of code goes

| Need | Put it here |
|---|---|
| Domain operation (create order, list items) | `NEWSCHEMA` / `NEWACTION` in `plugins/<feature>/schemas/` or `/actions/` |
| Feature HTTP API | `plugins/<feature>/index.js` (routes) + `schemas/` (actions) |
| Web page, health, webhook, OAuth redirect, upload, download | `controllers/` + `ROUTE('GET|POST|FILE …')` |
| WebSocket gateway | `controllers/` + `ROUTE('SOCKET …')` |
| Shared helper used by several features | `FUNC.*` assigned in `definitions/` |
| Helper used only by the views of one controller | a local `Func` object → `repository.func` ([section 20](#20-local-methods-for-views-repositoryfunc)) |
| Runtime map, cache, socket registry | `MAIN.*` |
| External integration with its own API (S3, payments, push, AI) | `/modules/<name>.js`, called as `MODS.<name>` |
| Database driver init | `definitions/db.js` |
| Auth | `AUTH()` in `definitions/auth.js` |
| Periodic work | `CRON()` or `ON('service')` in `definitions/` |
| Heavy isolated process | `/workers/<name>.js` |
| Config value | `CONF.key` from `config` |
| Request/response sugar needed by many actions | `Total.extend('$', …)` — rarely ([section 18](#18-extending-the-framework)) |

When unsure between `FUNC`, a module and an extension, use `FUNC`.

Do not add `src/`, `lib/`, `services/`, `repositories/`, `utils/` or `middleware/` directories.

### What this architecture is not

- not REST-resource controllers,
- not dependency injection,
- not one `require()` per file,
- not repository / unit-of-work classes,
- not Express middleware chains,
- not a generic Node.js folder layout with Total.js bolted on.

## 2. Project structure

```
index.js              start script: require('total5'); Total.run(...)
config                configuration (key : value) → CONF
config-debug          overlay for debug mode (optional)
config-release        overlay for release mode (optional)
definitions/          startup: AUTH, DATA init, FUNC.*, MAIN.*, CRON, ON()
modules/              integrations and shared code → MODS.<filename>
controllers/          HTTP / FILE / SOCKET routes, exports.install()
plugins/<feature>/
  index.js            metadata + ROUTE() registration
  schemas/*.js        NEWSCHEMA() actions (auto-loaded)
  public/             optional UI assets of the plugin
actions/              standalone NEWACTION() files (auto-loaded)
schemas/              shared NEWSCHEMA() files (optional)
workers/              Total.js workers (optional)
views/                templates (.html), layout.html is the default layout
public/               static files
databases/            data (MEMORIZE, downloaded JSON files)
tmp/                  temporary files
```

The framework loads JavaScript from these directories. You do not register them and you do not `require()` them.

**Which shape for which project**

| Project | Uses |
|---|---|
| Website without a database | `actions/`, `controllers/`, `views/`, `modules/`, `databases/` (MEMORIZE) |
| API backend | `definitions/`, `plugins/<feature>/`, `modules/`, a few `controllers/` (upload, health, sockets) |
| Both | all of the above; pages in `controllers/` call the same actions as the API |

**Load order** (verified in the total5 source):

```
.env / config → CONF
extensions → modules → actions → schemas → models → definitions → controllers → middleware → …
plugins/<id>/index.js, then that plugin's controllers, actions, schemas, definitions
```

Each file's `exports.install()` runs when that file is loaded. This means:

- a module from `/modules/` is already available when actions, definitions and controllers load,
- actions are defined before a controller calls them,
- definitions see modules; plugin schemas see the `FUNC.*` assigned in `definitions/`,
- **a module's top-level body must not call `FUNC.*`** — definitions have not run yet. Call `FUNC` from exported functions, which run after boot,
- action bodies run per request, long after boot, so they may use anything.

**Global variable convention:** the framework is available as `Total` and under the older shorthand `F` (the same object). In new code use the more readable `Total` (`Total.run()`, `Total.Fs`, `Total.error()`).

`index.js` stays tiny. Do not build an application container, logger factory or config loader around boot — Total.js already loads `config`, `.env`, definitions, modules, plugins, controllers, schemas and actions.

## 3. Running, debug and release

`index.js`:

```js
require('total5');
const options = {};
options.release = process.argv.includes('--release') || process.argv.includes('release');
Total.run(options);
```

| Command | Mode | Note |
|---|---|---|
| `node index.js` | debug | port **8000**, the watcher reloads changed controllers, actions, views and modules |
| `node index.js release` | release | views are cached, HTML is minified |

- In debug mode you **don't need to restart** the server after editing files — the watcher reloads them on its own (the log shows `--- UPD --- /controllers/…`). When `config` changes, the watcher restarts the whole process.
- A numeric argument sets the port: `node index.js 8001`.
- The debug runner creates `index.js.json`, `index.js.map` and `index.pid` in the project root → they belong in `.gitignore`.
- In production the app can listen on a unix socket: `options.unixsocket = '/path/app.socket'; options.unixsocket777 = true;`

> **Gotcha:** don't start Total.js via `node -e "require('total5'); Total.run()"`. The `flow-flowstream.js` module reads `process.argv[1]`, which doesn't exist with `-e`, and the app crashes. Always run a file.

Recommended `.gitignore`:

```
index.js.json
index.js.map
index.pid
tmp/
public/download/
```

## 4. Configuration

The `config` file uses the `key : value` format; lines starting with `//` are comments. Custom keys are available as `CONF.<key>`.

```
// Canonical address of the site
url                  : https://example.com
```

```js
// Canonical host: from config, otherwise from the request
function hostname($) {
	return CONF.url ? CONF.url.replace(/\/+$/, '') : $.hostname();
}
```

**Why `CONF.url`:** `$.hostname()` builds the address from the `Host` header and `X-Forwarded-Proto`. Behind a reverse proxy this easily produces `http://` instead of `https://`, or both `www.` and non-`www` → duplicate canonical URLs. A fixed domain in the config solves it once and for all (it also applies locally).

Built-in keys worth knowing: `CONF.$api` (the default API endpoint, `/api/`), `CONF.version`, `CONF.name`.

### More about `config`

`config` is not JSON. Keys become `CONF.<key>`; `config-debug` and `config-release` overlay it by mode.

```
name                     : My App
database                 : postgresql://user:pass@127.0.0.1:5432/app
salt                     : change-me
cookie_expires           : 14 days
allow_register (boolean) : true
api_key (env)            : MY_API_KEY
```

- A type in parentheses converts the value: `(boolean)`, `(number)`, `(array)`, `(json)` / `(object)`, `(date)`, `(random)` (generates a random string), `(hash)`. `(env)` copies `process.env.MY_API_KEY` into `CONF.api_key`.
- Declare the type of booleans and numbers. An untyped flag may arrive as the string `'true'`.
- Read config directly: `CONF.database`, `CONF.salt`. **Do not wrap it** in a settings module and do not load a parallel `config.json`.
- **`process.env` is for boot and deployment overrides only.** `index.js` may read `process.env.PORT` / `NODE_ENV`. Feature code reads `CONF`. If a value must come from the environment, use an `(env)` key, or assign it once in a definition:

```js
if (process.env.FEATURE_X != null)
	CONF.feature_x = process.env.FEATURE_X;
```

## 5. Coding style

Match these conventions in all application JavaScript.

### Formatting

- Tabs, not spaces (tab width 4).
- Semicolons at the end of statements.
- Short strings in single quotes `'...'`.
- No unnecessary whitespace; no braces around a single-statement `if` / `for` body.
- Classic `for` loops over `forEach()` where possible.
- **`var`-first.** Do not declare `const` inside function scopes; use `var` (or `let` for block bindings that must rebind). `const` at the top of a file is acceptable for a real npm import or a file-level constant object.

```js
// preferred
var user = await DATA.read('tbl_user').id($.user.id).promise($);
for (var i = 0; i < items.length; i++)
	FUNC.normalize(items[i]);

// avoid in application files
const user = await DATA.read('tbl_user').id($.user.id).promise($);
items.forEach((item) => FUNC.normalize(item));
```

### Names

Reuse the same names across projects, and use the same names in SQL and JS:

- `id`, `name`, `value`, `email`, `body`
- `items` or `arr` for collections; `item`, `tmp` for locals
- `dtcreated`, `dtupdated` (dates start with `dt`), `isremoved`, `ispublished` (booleans start with `is`)
- foreign keys: `userid`, `orderid`

| Thing | Convention | Example |
|---|---|---|
| File names | lowercase; kebab-case only for several words | `orders.js`, `ai-engine.js` |
| Schema names | PascalCase | `NEWSCHEMA('Orders', …)` |
| Standalone action ids | `Namespace\|action` | `NEWACTION('Orders\|create', …)` |
| Public API schema strings | snake_case | `orders_list`, `orders_create` |
| `FUNC` helpers | snake_case | `FUNC.hash_password` |
| Tables / views | `tbl_`, `cl_`, `view_` + singular | `tbl_order`, `view_user` |

### Comments

The code must be readable by a person, not only correct. Write a comment where a reader would otherwise have to guess; leave it out where the code already says the same thing.

Comment these places:

- **The top of a file**: what the file does, what it needs (other actions, tables, `config` keys) and how to call it, with one example of a call and of its result.
- **A constant with a meaning**: a limit, a timeout, a threshold, and why it has this value (`// The privacy policy promises 48 hours and the cleaning runs once an hour, so the limit is an hour shorter.`).
- **A decision that looks wrong or could be "simplified" into a bug**: a workaround, an order of steps that matters, a check that seems redundant, a deliberate omission.
- **A rule of the business or of the law** that the code enforces, in the words of that rule.
- **A regular expression, a long SQL query or a formula**: what it matches or computes, in one sentence.
- **A view**: a comment describing its model at the top ([section 19](#19-views-and-layout)).

Do not comment what the next line does (`// increments the counter`), do not paste the same `$` field dump into every action, and do not keep commented-out code. A comment that no longer matches the code is worse than none: change it together with the code.

```js
// avoid: repeats the code
// Checks the limit
if (BLOCKED({ ip: 'insert_' + $.ip }, LIMITS.insert)) {

// preferred: says why
// The offer waits for the confirmation of the e-mail: until then it is not processed and visitors do not see it.
model.isconfirmed = false;
```

Readable code needs fewer comments in the first place: name a value instead of explaining a number, return early instead of nesting, and split a function that does two things.

### Reusable code

Write every action, module and plugin so that it can be copied into another project and work there. Reuse by copying a file is the normal way of sharing code between Total.js projects, so a unit that cannot be copied is a unit that will be rewritten.

- **One unit, one file or folder.** An action file, a module or a `plugins/<feature>/` folder carries everything it needs: its constants, its small helpers, and next to it its SQL (`init.sql`), its data and its README.
- **Nothing of the project inside.** A URL, a token, a limit, a name of the product or an e-mail address is read from `config` (`CONF.<key>`) with a safe default, never written into the code ([section 4](#4-configuration)).
- **State the dependencies at the top.** The first comment lists the actions, tables and `config` keys the file relies on, so a person who copies it knows what else to bring.
- **Talk through public contracts.** Call other code with `ACTION()` / `$.action()`, `MODS.<name>` or an event, with declared `input` and a described output. Do not reach into the internals of another file.
- **Generic names.** `items`, `id`, `name`, `dtcreated` ([Names](#names) above) and generic mechanisms (a queue of e-mails, a cache table, a rate limit) instead of names of one product.
- **A small helper may be repeated.** A three-line function copied into two self-contained files is better than a shared file that both must then travel with. Move a helper to `FUNC` or `MODS` only when it is real shared behavior ([section 7](#7-sharing-code-modules-definitions-func-and-main)).

Before finishing a unit, ask: *could this file be dropped into an empty Total.js project and work after setting its `config` keys?* If not, find what ties it to this project and move that to `config` or to the caller.

### Errors and localization

User-facing messages use Total.js localization markup `@(…)`; transport failures use status codes:

```js
$.invalid('@(Invalid credentials)');
$.invalid(401);
$.invalid(403);
$.invalid(404);
```

These names exist after `require('total5')`. Never import them.

### Identifiers and hashes

```js
UID();                        // unique id (timestamp + counter + checksum) — use for primary keys
GUID();                       // a real 128-bit GUID
GUID(40);                     // random string of a given length — API keys, tokens

HASH('value', 'sha256');      // sha1, sha256, sha512, md5, crc32
String(password).sha256(CONF.salt);
id.sign(CONF.salt);           // 'id-signature', see signed downloads
```

### `NOW`

A shared `Date` refreshed by the framework timer so the app does not create `new Date()` all the time. It is the convention for `dtcreated` / `dtupdated`. For a precise "right now" in a security comparison, `new Date()` is still acceptable.

```js
NOW.add('14 days');
NOW.add('15 minutes');
```

### `ENCRYPTREQ` / `DECRYPTREQ`

Encrypts a payload and binds it to the request's user-agent (and to the IP when the 4th argument is `true`). This is the usual session token — do not introduce `jsonwebtoken` for the same job.

```js
var token = ENCRYPTREQ($, { id: session.id }, CONF.salt);
var data = DECRYPTREQ($, token, CONF.salt);     // null when it does not match
```

### `CACHE`

```js
CACHE.set('user_' + id, snapshot, '10 minutes');
var snapshot = CACHE.get('user_' + id);
CACHE.remove('user_' + id);
CACHE.reset('user_');   // removes keys containing this string
```

Invalidate on update/logout. Do not authorize from a stale cache when the database says the user is gone.

### `BLOCKED` and `ERROR`

```js
// max. 5 attempts per IP in 15 minutes
if (BLOCKED($, 5, '15 minutes')) {
	$.invalid('@(Too many attempts)');
	return;
}

BLOCKED($, -1);   // reset the counter, e.g. after a successful login

// ERROR('label') returns a callback that only logs the error
ACTION('Items|refresh').callback(ERROR('Source offline'));
```

### Mail

```js
MAIL(address, '@(Welcome)', 'mail/welcome', model);   // a view from /views/mail/welcome.html
HTMLMAIL(address, subject, html);
```

### Which bag for which data

| Data | Where |
|---|---|
| Configuration | `CONF` |
| Business records | PostgreSQL via `DATA`, or `MEMORIZE` for small data sets |
| Sessions, socket maps, registries, boot flags | `MAIN` |
| Values with an expiration | `CACHE` |
| Data that views read directly | `REPO` |
| A few minutes of scratch | `TEMP` |

## 7. Sharing code: modules, definitions, FUNC and MAIN

This is how Total.js shares application code. Internal `require()` is the wrong tool.

### Modules → `MODS`

Every `/modules/*.js` file is loaded by the framework and stored on `MODS`. The key is the file name without `.js` (override with `exports.id`).

`modules/storage.js`:

```js
// A module is the right place to require() an SDK the framework does not provide
const { S3Client, PutObjectCommand } = require('@aws-sdk/client-s3');

exports.install = function() {
	// optional startup; keep it short, long work belongs in ON('ready')
};

exports.putFile = async function(relpath, body, mime) {
	// talk to S3 / disk
};

exports.getUrl = async function(relpath) {
	// ...
};
```

Anywhere after boot — controllers, schemas, definitions, other modules:

```js
await MODS.storage.putFile(path, body, mime);
```

Callers use `MODS.storage`, never the SDK and never `require('../modules/storage')`. Modules load before controllers, so an alias at the top of a controller is safe:

```js
// Syntax highlighter (/modules/highlight.js)
const Highlight = MODS.highlight;

html = Highlight.highlight(html);
```

**What belongs in a module:** a reusable integration or library with its own surface — object storage, a mail provider wrapper that is more than `MAIL()`, a search / AI engine, a payment SDK, a push gateway, a syntax highlighter. A module exposes functions on `exports`, may read `CONF`, and may use `DATA` and `FUNC` from functions that run after boot.

**What does not:** `paginate()`, permission checks or SQL. Those are `FUNC` or actions.

### Definitions

`/definitions/*.js` is cross-cutting startup. Definitions are auto-loaded and need no `exports.install()`.

| File (typical) | Assigns |
|---|---|
| `db.js` | `querybuilderpg` → `DATA` |
| `auth.js` | `AUTH()` |
| `func.js` | generic `FUNC.*` (paginate, can, audit) |
| `func-mail.js`, … | more `FUNC.*`, split by concern |
| `sessions.js` | `MAIN.sessions` |
| `jobs.js` | `CRON()` / `ON('service')` |
| `realtime.js` | `FUNC.realtime_*`, `MAIN.ws_users` |
| `cors.js` | the single `CORS()` call |

Several definitions may assign `FUNC.*`. Do not grow one 2,000-line `func.js` of unrelated domain math.

### `FUNC`

Reusable application functions, assigned in definitions:

```js
FUNC.hash_password = function(password) {
	return String(password).sha256(CONF.salt);
};

FUNC.can = function($, perm) {
	var user = $.user;
	if (!user)
		return false;
	if (user.sa)
		return true;
	return (user.permissions || EMPTYARRAY).includes(perm);
};

FUNC.require_perm = function($, perm) {
	if (FUNC.can($, perm))
		return true;
	$.invalid(403);
	return false;
};

FUNC.audit = async function($, action, entity, entityid, payload) {
	try {
		await DATA.insert('tbl_audit', {
			id: UID(),
			userid: $.user ? $.user.id : null,
			entity: entity || null,
			entityid: entityid || null,
			action: action,
			payload: payload ? JSON.stringify(payload) : null,
			ip: $.ip,
			dtcreated: NOW
		}).promise();
	} catch (err) {
		Total.error(err, 'audit');
	}
};
```

Called from actions:

```js
if (!FUNC.require_perm($, 'users.manage'))
	return;
```

Good `FUNC` candidates: password hashing, permission checks, session create/refresh, safe user snapshots, audit/notify, small domain calculators used by more than one plugin.

Bad `FUNC` candidates: one plugin's private formatter (keep it local in the file), view helpers of one controller (local `Func`, [section 20](#20-local-methods-for-views-repositoryfunc)), HTTP handlers, raw SQL dumps of a whole feature.

### `MAIN`

Shared **runtime** data. Not configuration, not the database.

```js
var map = new Map();

MAIN.sessions = {
	get: async key => map.get(key) || null,
	set: async (key, value) => map.set(key, value),
	delete: async key => map.delete(key)
};

MAIN.ws_users = {};     // userid → Set of websocket clients
```

Use `MAIN` for the session cache, websocket connection maps, short-lived boot flags and process-local registries. Do not keep business records in `MAIN` when they belong in the database.

## 8. Actions: NEWACTION and NEWSCHEMA

Business logic belongs in actions. A controller or an API route only calls an action; nothing sits underneath it (no service classes, no repositories).

Total.js 5 has two first-class ways to declare actions. Both run through the same `$` and the same `ACTION()` caller.

| | Use it for | Lives in |
|---|---|---|
| `NEWSCHEMA('Name', fn)` + `schema.action()` | a group of related actions of one domain; routes are registered by the plugin | `plugins/<feature>/schemas/` |
| `NEWACTION('Name\|action', opt)` | one isolated action, optionally with its own `route` | `/actions/` |

### NEWACTION

```js
NEWACTION('Items|browse', {
	name: 'Browse items',
	input: 'search:String, page:Number, limit:Number',   // input schema
	route: '+API ?',                                     // API route (authorized users only)
	action: async function($, model) {
		// model = validated input
		$.callback(output);    // success
		// $.invalid(404);     // error
	}
});
```

### NEWSCHEMA

```js
// plugins/orders/schemas/orders.js
NEWSCHEMA('Orders', function(schema) {

	schema.action('list', {
		name: 'List orders',
		query: 'page:Number, limit:Number, search:String',
		action: async function($) {
			var response = await DATA.list('tbl_order')
				.where('isremoved', false)
				.autoquery($.query, 'id:String, name:String, dtcreated:Date', 'dtcreated_desc', 100)
				.promise($);
			$.callback(response);
		}
	});

	schema.action('read', {
		params: '*id:String',
		action: async function($) {
			var response = await DATA.read('tbl_order').id($.params.id).where('isremoved', false).error(404).promise($);
			$.callback(response);
		}
	});

	schema.action('create', {
		input: '*name:String, body:String',
		action: async function($, model) {
			model.id = UID();
			model.userid = $.user.id;
			model.dtcreated = NOW;
			await DATA.insert('tbl_order', model).promise($);
			$.success(model.id);
		}
	});

	schema.action('update', {
		params: '*id:String',
		input: '*name:String, body:String',
		action: async function($, model) {
			model.dtupdated = NOW;
			await DATA.modify('tbl_order', model).id($.params.id).error(404).promise($);
			$.success($.params.id);
		}
	});

	schema.action('remove', {
		params: '*id:String',
		permissions: 'orders_remove',
		action: async function($) {
			await DATA.modify('tbl_order', { isremoved: true, dtremoved: NOW }).id($.params.id).error(404).promise($);
			$.success($.params.id);
		}
	});
});
```

The routes are registered by the plugin ([section 10](#10-plugins)):

```js
ROUTE('+API /api/  -orders_list         --> Orders/list');
ROUTE('+API /api/  -orders_read/{id}    --> Orders/read');
ROUTE('+API /api/  +orders_create       --> Orders/create');
ROUTE('+API /api/  +orders_update/{id}  --> Orders/update');
ROUTE('+API /api/  -orders_remove/{id}  --> Orders/remove');
```

Schema files are auto-loaded. Never `require()` them.

### Options

| Option | Meaning |
|---|---|
| `name` | human-readable name (documentation) |
| `input` | schema of the payload → the `model` argument (`$.model`) |
| `query` | schema of query arguments → `$.query` |
| `params` | schema of route params → `$.params` |
| `output` | schema of the response; the output is transformed to match it |
| `route` | `NEWACTION` only: registers a route for the action — `'+API ?'`, `'-API ?'`, `'API ?'` or a classic `'+POST ?/tasks/create/'` |
| `action` | `function($, model)` — required |
| `user` | `true` → `$.user` must exist |
| `permissions` | `'perm1, perm2'` → the framework calls `UNAUTHORIZED($, …)`; `$.user.sa` / `$.user.su` pass everything |
| `sa` | `true` → `$.user.sa` or `$.user.su` must be `true` |
| `partial` | `true` → only the received fields are validated (PATCH-like updates) |
| `publish` | performs `NEWPUBLISH()` with the data: `true` copies input/output, a string is a schema, `+string` extends it |
| `extend` | a property name; extends the current payload with this action's response |

In `route`, `?` is replaced by `CONF.$api` (default `/api/`), so `'+API ?'` means `'+API /api/'`.

### Data schema

`name:Type, name:Type`, separated by commas. `*name` = required. Types are case-insensitive. A field without a type is a string.

| Kind | Types |
|---|---|
| Basic | `string`, `number`, `boolean`, `date`, `json` |
| Numbers | `tinyint`, `smallint`, `number` |
| Identifiers | `uid`, `guid` |
| Validated strings | `email`, `phone`, `zip`, `url`, `base64`, `color` (`#F0F0F0`), `icon` (`ti ti-home`) |
| Normalized strings | `name` (person's name, capitalized), `lowercase`, `uppercase`, `capitalize`, `capitalize2` |
| Data URI | `datauri` → `{ type, buffer }`, `datauri2` → a valid data URI string |
| Enum | `status:{draft\|published\|archived}` |
| Arrays | `tags:[String]`, `ids:[UID]` |
| Nested object | `address:{ street:String, city:String }` |
| Array of objects | `rows:[name:String, age:Number]` |
| Linked schema | `profile:@Profile` — declared as `NEWSCHEMA('@Profile', '*name:String, age:Number')` |

The schema is designed for one level of properties; keep payloads flat.

### The action `$` (Options)

> **The most common mistake:** an action's `$` is an **Options** object, not the HTTP controller. It has no `$.json()`, `$.view()`, `$.file()` or `$.html()`. Finish every action with `$.success()`, `$.callback()` or `$.invalid()`.

| Read | Meaning |
|---|---|
| `model` / `$.model` | validated `input` |
| `$.query`, `$.params` | validated query / route params |
| `$.user` | the session from `AUTH()` |
| `$.headers`, `$.ip`, `$.ua`, `$.language`, `$.url` | request details |
| `$.files` | uploaded files |
| `$.controller` | the HTTP controller when the action was called from a route (may be missing) |

| Respond | Result |
|---|---|
| `$.success()` | `{ success: true }` |
| `$.success(value)` | `{ success: true, value: value }` (built by `DEF.onSuccess`) |
| `$.callback(payload)` | the raw payload — lists, rows, query results |
| `$.invalid('@(Message)')` | validation / business error |
| `$.invalid(404)` | error with an HTTP status |
| `$.done(value)` | returns a Node-style callback: error → `$.invalid`, otherwise `$.success(value)` |
| `$.redirect(url)` | redirect |

Do not rebuild the envelope by hand (`$.callback({ success: true, value: id })`). Respond exactly once, and `return` after `$.invalid()`.

`.promise($)` on `DATA`, `ACTION` and `RESTBuilder` forwards errors to `$.invalid()` automatically and stops the action, so no `try/catch` is needed around them.

### Calling actions

```js
// from another action — errors go to $.invalid
var id = await ACTION('Orders/create', { name: 'X' }).user($.user).promise($);

// from a page controller
ACTION('Items|browse', { search: 'grid', page: 2 }).callback(function(err, response) {
	if (err)
		notfound($);
	else
		$.view('browse', response).repository.func = Func;
});

// fire and forget
ACTION('Items|refresh').callback(ERROR('Source offline'));
```

The id is the schema name plus the action (`Orders/create`) or the `NEWACTION` id (`Items|browse`). Builder methods: `.query({…})`, `.params({…})`, `.user(session)`, `.config({…})` — they supply what a route would otherwise supply.

### Internal actions

`route: '+API ?'` registers the action for signed-in users only. In an app without an `AUTH()` definition nobody can call it from outside → a safe "internal" action that is still callable through `ACTION()`. An action with no `route` and no `ROUTE()` is internal by definition.

### Reusable preconditions

A route may chain actions; `(response)` marks the one whose output is returned:

```js
ROUTE('+API /api/  +orders_create  --> Orders/check Orders/insert (response)');
```

Use it for reusable preconditions (uniqueness, ownership). Do not build hidden pipelines with side effects.

## 9. Controllers and routing

Controllers own HTTP, files and sockets: web pages, health, webhooks, SSO redirects, multipart uploads, file downloads and WebSocket gateways. They do not own domain rules — those are actions ([section 8](#8-actions-newaction-and-newschema)).

### Two different `$` objects

| Context | `$` is | Has |
|---|---|---|
| `ROUTE('GET /', fn)` | the HTTP **controller** | `$.view`, `$.json`, `$.html`, `$.text`, `$.xml`, `$.file`, `$.stream`, `$.binary`, `$.filefs`, `$.redirect`, `$.cookie`, `$.response`, plus `$.success`, `$.invalid`, `$.callback` |
| `NEWACTION` / `NEWSCHEMA` / `AUTH` | **Options** | `$.success`, `$.invalid`, `$.callback`, `$.done`, `$.redirect` — **not** `$.json` / `$.view` / `$.file` |

Request data on the controller:

| Field | Meaning |
|---|---|
| `$.query` | query string object |
| `$.body` | parsed body |
| `$.params` | route params (`/items/{id}/` → `$.params.id`) |
| `$.headers` | request headers |
| `$.files` | uploaded files (`@upload` routes) |
| `$.user` | the session set by `AUTH()` |
| `$.ip`, `$.ua`, `$.mobile`, `$.language` | client details |
| `$.url` | relative URL; `$.split` = its segments |
| `$.hostname()` | origin built from the request headers |

### Page routes

`controllers/default.js`:

```js
exports.install = function() {
	ROUTE('GET /refresh/ <20s', refresh);            // timeout 20 s
	ROUTE('GET /', browse);
	ROUTE('GET /items/', browse);
	ROUTE('GET /items/{id}/', detail);               // $.params.id
	ROUTE('GET /items/{id}/preview/', preview);
	ROUTE('FILE /sitemap.xml', sitemap);             // a "static" file generated by code
	ROUTE('FILE /robots.txt', robots);
	ROUTE('#404', notfound);                         // fallback for unknown URLs
};
```

| Notation | Meaning |
|---|---|
| `GET /path/` | regular route |
| `+GET /path/` | authorized users only (`-GET` unauthorized only) |
| `<20s`, `<5m` | route timeout |
| `{id}` | parameter → `$.params.id` |
| `FILE /x.xml` | file route (same channel as static files) |
| `#404`, `#500` | internal fallback routes |

### Controller responses

| Method | Use |
|---|---|
| `$.view(name, model)` | renders a view, **returns a View object** (`.repository`) |
| `$.html(string)` | raw HTML |
| `$.xml(string)`, `$.text(string)` | XML / text |
| `$.binary(buffer, type, filename)` | binary data; with `filename` as an attachment |
| `$.file(path)` | a file from disk |
| `$.redirect(url, true)` | `true` = 301 (permanent) |
| `$.invalid(code)` | error — **returns JSON**, not HTML! |

Headers and status:

```js
$.response.status = 404;
$.response.headers['X-Robots-Tag'] = 'noindex, nofollow';
$.response.headers['Content-Disposition'] = 'attachment; filename="example.html"';
$.response.minify = false;   // turns off minification of the HTML/JS response
```

### An HTML 404 page (instead of JSON)

Both `$.invalid(404)` and `$.invalidsafe(404)` return an empty JSON body — not suitable for a website. A custom page:

```js
function notfound($) {
	$.response.status = 404;
	$.view('404').repository.func = Func;
}
```

and `ROUTE('#404', notfound)` uses it for completely unknown addresses as well.

### Validating input against duplicate content

```js
var page = query.page ? +query.page : 1;
if (!(page > 0) || page % 1 !== 0) {     // ?page=abc, ?page=1.5, ?page=-1
	notfound($);
	return;
}
```

and a 301 redirect for non-canonical IDs (`/items/My-Item/` → `/items/my-item/`):

```js
else if (response.id !== $.params.id)
	$.redirect(response.url, true);
```

### Initialization in a controller

```js
exports.install = function() {
	ROUTE('GET /docs/', view);
	setImmediate(load);     // more reliable than ON('ready') in a controller
};
```

### More controller responses

```js
$.json(obj);                        // raw JSON
$.success(value);                   // { success: true, value }
$.callback(err, value);             // Node-style: error → $.invalid, otherwise JSON
$.stream('application/pdf', stream, 'name.pdf');
$.file('/abs/path', 'name.pdf');    // with a download name
$.filefs('files', id);              // a file from FILESTORAGE
$.proxy(opt);
$.cookie('name');                   // read
$.cookie('name', value, '7 days');  // write
```

In a JSON endpoint written as a controller (webhook, upload), use `$.success(value)` / `$.invalid()` — never a hand-rolled `$.json({ ok: true, data })`.

### Auth flags

The first character of the method is the auth flag. It is evaluated from `AUTH()` ([section 11](#11-authentication-and-authorization)).

| Prefix | Meaning |
|---|---|
| `+GET` / `+POST` / `+API` / `+SOCKET` | authorized only (`AUTH` called `$.success(user)`) |
| `-GET` / `-API` | unauthorized only (login, register) |
| `GET` / `API` | either; `$.user` is set when a session exists |

Do not parse or decrypt tokens in a handler; `$.user` is already there.

### API routing — one gateway

Feature/JSON work goes through one endpoint. `API` is a `POST` with a fixed JSON envelope `{ schema, data }`:

```js
ROUTE('+API /api/  -orders_list          --> Orders/list');
ROUTE('+API /api/  -orders_read/{id}     --> Orders/read');
ROUTE('+API /api/  +orders_create        --> Orders/create');
ROUTE('+API /api/  %orders_patch/{id}    --> Orders/patch');
ROUTE('-API /api/  +auth_login           --> Auth/login');
```

Two different signs — do not confuse them:

| Sign | Position | Meaning |
|---|---|---|
| `+API` / `-API` / `API` | before the method | authorization |
| `+name` | before the schema string | the operation **has a payload** (`data` is validated against `input`) |
| `-name` | before the schema string | the operation has **no payload** (list, read, remove by id) |
| `%name` | before the schema string | **partial** payload — only the received fields are validated |

The sign is stripped from the public name; clients call `orders_list`, not `-orders_list`.

```http
POST /api/
Content-Type: application/json
x-token: <session>

{ "schema": "orders_read/abc123", "data": {} }
```

Params follow the name (`orders_read/abc123`), query arguments are appended as a query string (`orders_list?page=2&search=grid`).

Responses: `$.success(id)` → `{ "success": true, "value": "…" }`, `$.callback(obj)` → the object itself, `$.invalid()` → an array of errors `[{ "error": "…" }]` with the matching HTTP status.

Use ordinary HTTP routes only for pages, files, health, webhooks, SSO redirects and WebSockets.

### Size, timeout and flags

Everything is written inside the route string:

```js
ROUTE('+POST /upload/ @upload <10MB', upload);   // multipart only, max. 10 MB
ROUTE('GET /refresh/ <20s', refresh);            // timeout 20 s
ROUTE('POST /hooks/stripe/ <1MB', webhook);
ROUTE('GET /admin/ #session', admin);            // named middleware
```

| Notation | Meaning |
|---|---|
| `<10MB`, `<500kB` | max. payload size (the default comes from the config) |
| `<20s`, `<5m`, `<1h` | timeout — **`<5m` is five minutes, `<5MB` is five megabytes** |
| `@upload` | accepts `multipart/form-data` only |
| `@json`, `@xml`, `@xhr`, `@mobile`, `@robot`, `@debug`, `@release` | the route matches only for such requests |
| `@text`, `@binary` | WebSocket message type (the default is JSON) |
| `#name` | applies `MIDDLEWARE('name', …)` |

> **Gotcha:** the Total.js 4 form `ROUTE('POST /upload/', upload, ['upload'], 1024)` does not work in Total.js 5. The signature is `ROUTE(url, action, [size])`; flags go into the URL with `@`.

Uploads are covered in [section 14](#14-filesystem-path-and-uploads), sockets in [section 17](#17-websockets).

### CORS

Call it **once** — in `definitions/cors.js` or the default controller, never in every plugin:

```js
CORS();                                                     // allow all — fine for native mobile + token auth
CORS('https://app.example.com,http://localhost:3000');      // explicit origins
```

### What controllers should not do

- parse auth tokens when `AUTH()` already did,
- contain SQL or business rules for a feature that has actions,
- invent `sendSuccess(res)` helpers or Express-style middleware,
- `require()` modules or Node `fs` / `path`.

## 10. Plugins

A plugin is the feature unit of a backend. Total.js auto-loads `/plugins/<id>/index.js` into `PLUGINS.<id>` and also the plugin's own `schemas/`, `actions/`, `controllers/` and `definitions/`. The identifier is the directory name (`plugins/orders` → `PLUGINS.orders`).

```
plugins/
	orders/
		index.js            metadata + ROUTE() in exports.install()
		schemas/
			orders.js       NEWSCHEMA('Orders', ...)  (auto-loaded)
		public/             optional admin/UI assets
			index.html
			form.html
```

Two common shapes:

1. **API feature plugin** (JSON backends, mobile APIs) — `index.js` registers routes, `schemas/` holds the actions. No UI.
2. **Admin / UI plugin** — the same server entry plus `public/` HTML for a Total.js client.

### `index.js`

```js
exports.name = '@(Orders)';
exports.icon = 'ti ti-receipt';
exports.position = 10;
exports.permissions = [{ id: 'orders', name: 'Orders' }, { id: 'orders_remove', name: 'Remove orders' }];
exports.visible = user => user.sa || user.permissions.includes('orders');

exports.install = function() {
	ROUTE('+API ?  -orders_list         --> Orders/list');
	ROUTE('+API ?  -orders_read/{id}    --> Orders/read');
	ROUTE('+API ?  +orders_create       --> Orders/create');
	ROUTE('+API ?  +orders_update/{id}  --> Orders/update');
	ROUTE('+API ?  -orders_remove/{id}  --> Orders/remove');
	// FILE / SOCKET / upload routes of this feature also belong here
};
```

| Export | Type | Meaning |
|---|---|---|
| `name` | String | display name, with localization markup `@(…)` |
| `icon` | String | `ti ti-<icon>` |
| `position` | Number | order in the navigation |
| `permissions` | Array | optional permission catalog `[{ id, name }]` introduced by the plugin |
| `visible` | Function(user) | returns whether the plugin is visible for the session; `user.sa` / `user.su` see everything |
| `hidden` | Boolean | hides the plugin in the menu (it is still evaluated on the client) |
| `import` | String | optional file from the plugin's `public/` imported by the client app while it loads; most plugins don't use it |
| `install` | Function | registers routes |

`name`, `icon`, `position`, `visible` and `permissions` matter for a Total.js admin/UI client. A pure API plugin can keep only `install`.

### Rules

- `index.js` is the route table; the actions live in `schemas/`. A tiny plugin (one or two actions) may declare `NEWACTION` with `route: '+API ?'` directly in `index.js`.
- Do not `require()` a plugin schema from another file. Do not turn a plugin into an npm-style package of classes.
- Plugins talk to each other through `ACTION()`, `FUNC` and events (`EMIT` / `ON`), not through imports.
- Optional product modules can skip registration:

```js
exports.install = function() {
	if (!CONF.allow_orders)
		return;
	ROUTE('+API ?  -orders_list --> Orders/list');
};
```

## 11. Authentication and authorization

Authorization is **one delegate**: `AUTH()`. It runs for every request except static files, and its result drives the `+` / `-` route flags. `AUTH()` answers *who*; actions answer *whether*.

### `AUTH()`

```js
// definitions/auth.js
AUTH(async function($) {

	var token = FUNC.read_header_token($);
	if (!token || token.length < 20) {
		$.invalid();
		return;
	}

	var data = DECRYPTREQ($, token, CONF.salt);
	if (!data || !data.id) {
		$.invalid();
		return;
	}

	var session = await MAIN.sessions.get(data.id);
	if (!session)
		session = await DATA.read('tbl_session').id(data.id).promise();

	if (!session || (session.dtexpire && session.dtexpire < NOW)) {
		$.invalid();
		return;
	}

	var user = await FUNC.refresh_session(session);
	if (user)
		$.success(user);
	else
		$.invalid();
});
```

- `$.success(user)` → `$.user` is set; `+` routes match.
- `$.invalid()` → unauthorized; `-` routes match.
- Unprefixed routes (`API`, `GET`) run either way and may read `$.user`.
- `$` here is an Options object (no `$.json`). Inside `AUTH()` a bare `$.invalid()` is enough; in an action use `$.invalid(401)` for an explicit status.

The simplest possible delegate:

```js
AUTH(function($) {
	if ($.headers['x-token'] === CONF.token)
		$.success({ id: 'admin', name: 'Admin', sa: true });
	else
		$.invalid();
});
```

### Token headers

Accept a small compatibility set; prefer `x-token`:

```js
FUNC.read_header_token = function($) {
	var headers = $.headers || EMPTYOBJECT;
	var token = headers['x-token'] || headers.token || '';
	var auth = headers.authorization || '';
	if (!token && auth && auth.substring(0, 7).toLowerCase() === 'bearer ')
		token = auth.substring(7).trim();
	return token || '';
};
```

Tokens are opaque: the encrypted session id (`ENCRYPTREQ`). Do not put roles into a JWT that the client can read and the server trusts blindly. For a browser app the same token may travel in a cookie (`$.cookie('name', token, '14 days')`).

### Sessions

Create in `FUNC`, cache on `MAIN`, persist through `DATA`:

```js
FUNC.create_session = async function($, userid) {

	var session = {};
	session.id = UID();
	session.userid = userid;
	session.ip = $.ip;
	session.dtexpire = NOW.add(CONF.cookie_expires || '14 days');
	session.dtcreated = NOW;

	await DATA.insert('tbl_session', session).promise();

	var user = await FUNC.refresh_session(session);
	user && await MAIN.sessions.set(session.id, user);

	return { token: ENCRYPTREQ($, { id: session.id }, CONF.salt), user: FUNC.user_safe(user) };
};
```

- `FUNC.refresh_session(session)` loads the current user (id, name, `sa`, `permissions`) and returns `null` when the user is gone or removed.
- `FUNC.user_safe(user)` must strip password hashes, reset tokens and secrets.
- Logout removes the row, the `MAIN.sessions` entry and any `CACHE` snapshot.
- Expire old sessions in `ON('service')` or `CRON()` ([section 16](#16-periodic-tasks-cron-events-and-workers)).

### Login

```js
// plugins/auth/schemas/auth.js
NEWSCHEMA('Auth', function(schema) {

	schema.action('login', {
		input: '*email:Email, *password:String',
		action: async function($, model) {

			if (BLOCKED($, 5, '15 minutes')) {
				$.invalid('@(Too many attempts)');
				return;
			}

			let user = await DATA.read('tbl_user')
				.fields('id')
				.where('email', model.email)
				.where('password', FUNC.hash_password(model.password))
				.where('isremoved', false)
				.promise($);

			if (!user) {
				$.invalid('@(Invalid credentials)');
				return;
			}

			BLOCKED($, -1);
			$.success(await FUNC.create_session($, user.id));
		}
	});

	schema.action('me', {
		action: function($) {
			$.callback(FUNC.user_safe($.user));
		}
	});
});
```

```js
// plugins/auth/index.js
exports.install = function() {
	ROUTE('-API ?  +auth_login   --> Auth/login');    // public
	ROUTE('+API ?  -auth_me      --> Auth/me');       // session required
	ROUTE('+API ?  -auth_logout  --> Auth/logout');
};
```

Public login/register stay on `-API`. Protected work stays on `+API`. A public list that can personalize when a user is present uses an unprefixed `API` route and reads `$.user`.

### Permissions

Declarative, on the action:

```js
schema.action('remove', {
	permissions: 'orders_remove',   // UNAUTHORIZED($, 'orders_remove'); sa/su pass
	// sa: true,                    // super admin only
	// user: true,                  // any signed-in user
	action: async function($) { ... }
});
```

`UNAUTHORIZED` reads `$.user.permissions` (an array of strings) and lets `$.user.sa` / `$.user.su` through, so keep that shape on the session. Row ownership belongs in the query, not in JavaScript: `.where('userid', $.user.id)`.

### API keys and sockets

- If you accept `x-api-key`, resolve it **inside** `AUTH()` and map it to the same session shape (`id`, `permissions`, `auth_source: 'api'`). No second middleware.
- `AUTH()` also runs at the WebSocket handshake, so `+SOCKET` works when the token travels in a cookie or header. A browser cannot set custom headers on a WebSocket; then authenticate with the first message ([section 17](#17-websockets)).

### Do not

- implement Passport / `jsonwebtoken` middleware,
- decode tokens in every controller,
- store the password hash on `$.user`,
- trust a `role` or `userid` field sent by the client,
- split identity by URL path unless you truly have separate apps; prefer one user with roles/permissions.

## 12. PostgreSQL: DATA and QueryBuilder

Application code talks to PostgreSQL through **`DATA`** (QueryBuilder). Do not add repositories, ORMs or `require('pg')` inside actions. Views (`view_user`) belong in SQL, not in a JS repository.

### Init

```js
// definitions/db.js — a legitimate require of an npm package
require('querybuilderpg').init('', CONF.database, 1, ERROR('DB'));
```

The empty name registers the default connection used by `DATA`; `1` is the pool size. `config`: `database : postgresql://user:pass@127.0.0.1:5432/app`.

`DATA` is the shared singleton; each call executes immediately. `DB()` creates a **new** controller — older docs use it everywhere; in Total.js 5 code prefer `DATA`.

### Operations

Each returns a QueryBuilder:

```js
DATA.find('tbl_user');                          // array of rows
DATA.list('tbl_user');                          // paginated { items, count, page, pages, limit }
DATA.read('tbl_user');                          // one row or null
DATA.insert('tbl_user', { id: UID(), name: 'Created', dtcreated: NOW });
DATA.modify('tbl_user', { name: 'Updated', dtupdated: NOW });   // alias: DATA.update
DATA.remove('tbl_user');
DATA.check('tbl_user');                         // exists? → Boolean
DATA.count('tbl_user');
DATA.scalar('tbl_user', 'avg', 'age');
DATA.query('SELECT id, name FROM tbl_user WHERE email=$1', [email]);
```

`modify` and `remove` without a filter touch the **whole table** — always add `.id()` / `.where()`.

### Builder methods

Filters combine with **AND** unless you use `.or()`.

```js
builder.fields('id,name,dtcreated');
builder.id(value);                         // id = value
builder.userid(value);                     // userid = value
builder.where(column, value);
builder.where(column, '>', value);         // = > < >= <= <>
builder.between(column, a, b);
builder.in(column, array);
builder.search(column, value, [operator]); // ILIKE; operator: '*' (default), 'beg', 'end'
builder.query('isremoved=FALSE');          // raw fragment — trusted SQL only
builder.or(function() {
	this.where('name', 'Peter');
	this.where('name', 'Anna');
});
builder.sort('dtcreated', true);           // true / 'desc' → DESC
builder.take(50);
builder.skip(50);
builder.paginate(page, limit, maxlimit);
builder.error(404);                        // error when nothing was found / changed
builder.error('@(Already exists)', true);  // reverse: error when a row exists
builder.autoquery(query, schema, default_sort, default_maxlimit);
builder.callback(function(err, response) { ... });
builder.promise($);                        // Promise; errors go to $.invalid
```

### Recipes

```js
// read or 404
let user = await DATA.read('tbl_user').id($.params.id).where('isremoved', false).error(404).promise($);

// insert
model.id = UID();
model.dtcreated = NOW;
await DATA.insert('tbl_order', model).promise($);

// update or 404
await DATA.modify('tbl_order', { name: model.name, dtupdated: NOW }).id(id).error(404).promise($);

// soft delete
await DATA.modify('tbl_order', { isremoved: true, dtremoved: NOW }).id(id).error(404).promise($);

// uniqueness
await DATA.check('tbl_user').where('email', model.email).error('@(E-mail is already used)', true).promise($);

// many rows by ids — never a read in a loop
let rows = await DATA.find('tbl_user').fields('id,name').in('id', ids).promise($);
```

### Lists with `autoquery()`

`autoquery()` reads `$.query` and builds filters, sorting, paging and the field list from a schema string. Only the listed fields can be filtered, sorted or returned.

```js
var response = await DATA.list('view_order')
	.where('isremoved', false)
	.autoquery($.query, 'id:String, name:String, email:String, dtcreated:Date', 'dtcreated_desc', 100)
	.promise($);

$.callback(response);   // { items, count, page, pages, limit }
```

The client then controls the list through the query string: `page`, `limit`, `sort=name_asc`, `fields=id,name`, and one argument per filtered field (`name=…`). Return the `DATA.list` result as it is; do not invent another list envelope. Use views for denormalized lists.

### `.promise($)` vs `.promise()`

- `.promise($)` — an error (including `.error(404)`) is sent through `$.invalid()` and the action stops. Use it in actions.
- `.promise()` — rejects; you must `try/catch`. Use it outside a request (`AUTH`, cron, `FUNC` helpers without `$`).

### Builder first, raw SQL last

Write a query with the builder (`DATA.read` / `find` / `list` / `count` / `insert` / `modify` / `remove`) whenever it can express it. It is a little slower than a hand-written statement, but a person reads it at a glance: the table, the fields and each condition are on their own, values are bound for you and `.error(404)` replaces the `if (!rows.length)` that follows every raw query.

```js
// avoid: the reader has to parse the SQL and the handling of an empty result
var rows = await DATA.query('SELECT id,name,email FROM tbl_item WHERE id=$1 AND email=$2 AND isremoved IS NOT TRUE LIMIT 1', [model.id, email]).promise($);
if (!rows.length) {
	$.invalid(404);
	return;
}
var item = rows[0];

// preferred
var item = await DATA.read('tbl_item').fields('id,name,email').id(model.id).where('email', email).where('isremoved IS NOT TRUE').error(404).promise($);
```

What the builder covers and is easy to miss:

```js
// A condition the builder has no method for: where() with one argument is a raw fragment (the same as query())
DATA.read('tbl_access').id(id).where('dtexpire > timezone(\'utc\', now())');

// A value computed by the database: a key that starts with "=" is written as raw SQL
DATA.insert('tbl_access', { id: UID(), email: email, '=dtcreated': 'timezone(\'utc\', now())' });
DATA.modify('tbl_item', { isremoved: true, '=dtremoved': 'timezone(\'utc\', now())' }).id(id).error(404);

// The changed or removed rows: returning() (with first() one row, without it an array)
DATA.modify('tbl_item', { isconfirmed: true, token: null }).where('token', token).first().returning('id');
DATA.remove('tbl_item').where('dtend < timezone(\'utc\', now())').returning('pictures');

// A number of rows
var count = await DATA.count('tbl_access').where('email', email).promise($);
```

A raw fragment and a `=` value are trusted SQL: constants and names of columns only, never a value from a request.

Keep `DATA.query()` for what the builder cannot say clearly: joins and subqueries, `GROUP BY` and aggregates, expressions in the list of fields (`COALESCE(…) AS name`, `CASE` — `fields()` splits its argument at commas), a parameter inside an expression (`$1 = ANY(pictures)`), PostGIS and SQL that is built dynamically. Do not replace one join with several builder calls in a loop.

```js
var rows = await DATA.query('SELECT c.kind, COUNT(*)::int AS count FROM tbl_item i JOIN cl_item c ON c.id=i.typeid GROUP BY 1', []).promise($);
```

**Never concatenate request values into SQL.** `builder.query('…')` is for trusted fragments only.

### SQL style

- Table and field names all lowercase; tabs; `;` at the end of every command; no needless type casts (`name<>'x'`, not `name<>'x'::text`).
- Divide scripts: TABLES, VIEWS, STORED PROCEDURES/FUNCTIONS, INDEXES.
- Prefixes, singular: `tbl_user`, `cl_type` (codelists), `view_user`, `sp_user` (procedures), `fn_user` (functions).
- Dates start with `dt` and are stored in UTC: `dtcreated`, `dtupdated`, `dtpaid`.
- Booleans start with `is`: `ispaid`, `isremoved`, `ispublished`.
- Identifiers: `id` (primary key, `text` from `UID()`), foreign keys `userid`, `productid`.
- `text` instead of `varchar`.
- The same names in different tables (`name`, `body`); short names; whenever possible every table has `id`, `name` and `dtcreated`.

Keep this order of fields:

```sql
CREATE TABLE "public"."tbl_channel_message" (

	-- IDENTIFIERS FIRST
	"id" text NOT NULL,
	"userid" text,
	"channelid" text,

	-- MAIN FIELDS
	"body" text,

	-- NUMBERS
	"countupdate" INT2 DEFAULT 0,
	"countviews" INT2 DEFAULT 0,

	-- BOOLEANS
	"ispinned" bool DEFAULT FALSE,
	"isremoved" bool DEFAULT FALSE,

	-- DATES LAST
	"dtupdated" timestamp,
	"dtremoved" timestamp,
	"dtcreated" timestamp DEFAULT timezone('utc'::text, now()),

	-- FOREIGN KEYS
	CONSTRAINT "tbl_channel_message_userid_fkey" FOREIGN KEY ("userid") REFERENCES "public"."tbl_user"("id") ON DELETE CASCADE,

	PRIMARY KEY ("id")
);
```

## 13. Data without a database: MEMORIZE and REPO

Small and medium data sets (hundreds to thousands of records) don't need a database. The whole catalog lives in memory and is persisted to a JSON file.

`actions/items.js`:

```js
// Default values
REPO.db = MEMORIZE('db');          // databases/memorize_db.json

if (!REPO.db.items)
	REPO.db.items = EMPTYARRAY;

if (!REPO.db.pictures)
	REPO.db.pictures = {};
```

- `MEMORIZE(name)` returns an object loaded from `databases/memorize_<name>.json` and adds methods to it:
  - `.save()` — saves with a **10-second delay** (debounce); multiple calls are merged into one write,
  - `.set(key, value)` — sets a value and calls `save()`.
- `REPO` is the global application object, also available in views (`@{REPO.db.items.length}`).
- `EMPTYARRAY` / `EMPTYOBJECT` are shared empty values of Total.js (never mutate them).

**When it's not enough:** when the data doesn't fit in memory, or when you need transactions or writes from multiple processes.

### `REPO` vs `MAIN`

`REPO` is the bag that views can read, which is why the catalog lives there. Process-only runtime state (sessions, socket maps) belongs on `MAIN`, and nothing durable belongs in `TEMP` ([section 6](#6-globals)).

Move to PostgreSQL ([section 12](#12-postgresql-data-and-querybuilder)) as soon as the app has user accounts, writes coming from requests, or data that does not fit comfortably in memory.

## 14. Filesystem, PATH and uploads

Total.js already wraps Node's filesystem and path APIs. Application code does not `require('fs')` or `require('path')`.

### `PATH`

Each helper returns the directory, or joins a relative piece onto it:

```js
PATH.root()                 PATH.root('package.json')
PATH.public()               PATH.public('uploads/' + id + '.jpg')
PATH.private()
PATH.databases()            PATH.databases('items.json')
PATH.logs()                 PATH.logs('audit.log')
PATH.temp()                 PATH.temp('export.csv')      // alias: PATH.tmp()
PATH.modules()   PATH.plugins()   PATH.templates()
```

```js
PATH.join(a, b, c);
PATH.exists(filename, function(exists, size, isfile) { ... });   // without a callback → Promise
PATH.mkdir(directory);           // recursive, sync
PATH.unlink(file_or_array);
PATH.rmdir(dir_or_array);
PATH.verify(PATH.temp('exports'));   // creates the directory when missing (remembered)

PATH.fs.readFileSync(PATH.temp(name));   // PATH.fs === Total.Fs === node:fs
await Total.readfile(filename, 'utf8');
```

> **`PATH.verify()` is not a security check.** It only ensures a directory exists. It does not sanitize `../` or user-controlled segments.

### Paths from request data

1. Generate the file name yourself (`UID()` + an allowed extension).
2. Join it onto a known root (`PATH.public('uploads')`, `PATH.temp()`).
3. Reject absolute input and `..`.
4. Then write.

```js
var ext = U.getExtension(file.filename).toLowerCase();
if (!['png', 'jpg', 'jpeg', 'webp', 'pdf'].includes(ext)) {
	$.invalid('@(Unsupported file type)');
	return;
}
var filename = PATH.public('uploads/' + UID() + '.' + ext);
```

### Node built-ins on `Total`

```js
Total.Fs        // node:fs        also PATH.fs
Total.Path      // node:path      also PATH.join
Total.Http      Total.Https
Total.Crypto    Total.Zlib      Total.Stream
Total.Url       Total.Os        Total.Util      // node:util — Total.js helpers are U / Utils
Total.Net       Total.Dns       Total.Tls
Total.Child     // child_process
Total.Worker    // worker_threads
```

Prefer `PATH.*`, `HASH()` and `RESTBuilder` over reaching for these. Use `Total.Https` only when `RESTBuilder` / `REQUEST` cannot express the call.

### Upload route

A multipart upload is a normal HTTP route, not an API envelope:

```js
exports.install = function() {
	ROUTE('+POST /upload/ @upload <10MB', upload);
	ROUTE('FILE /download/*.*', download);
};

async function upload($) {

	var file = $.files[0];
	if (!file) {
		$.invalid('@(No file uploaded)');
		return;
	}

	if (!FUNC.require_perm($, 'files_upload'))
		return;

	var id = UID();
	var meta = await file.fs('files', id);     // stores the bytes in FILESTORAGE('files')

	await DATA.insert('tbl_file', {
		id: id,
		userid: $.user.id,
		name: file.filename,
		type: file.type,
		size: file.size,
		dtcreated: NOW
	}).promise($);

	$.success({ id: id, name: file.filename, url: '/download/' + id.sign(CONF.salt) + '.' + meta.ext });
}
```

An uploaded file has `file.filename`, `file.type`, `file.size`, `file.path` (a temporary path), `file.width` / `file.height` for images, and:

```js
await file.read();                // Buffer
await file.fs('files', id);       // → FILESTORAGE, returns the metadata
await file.move(filename);        // move to a path
await file.copy(filename);
```

The route already requires a session (`+POST`); do not decrypt the token again in the handler.

### FileStorage

`FILESTORAGE(name)` is the framework-native blob storage on disk (`databases/fs-<name>/`). Use it whenever files stay on the server; use a `/modules/storage.js` module (called through `MODS.storage`) for S3 or another object store.

```js
var meta = await file.fs('files', id);    // store an upload
$.filefs('files', id);                    // send it back (controller)
FILESTORAGE('files').remove(id);
```

### Signed download ids

When files are served from a public `FILE` route, sign the id so clients cannot guess keys:

```js
// url: /download/{id.sign(CONF.salt)}.jpg
function download($) {
	var name = $.split[1] || '';
	var index = name.lastIndexOf('.');
	var hash = index === -1 ? name : name.substring(0, index);
	var id = hash.substring(0, hash.indexOf('-', 10));
	if (id && hash === id.sign(CONF.salt))
		$.filefs('files', id);
	else
		$.invalid(404);
}
```

### File rules

- Metadata in the database, bytes in storage.
- Return ids and URLs, never raw server paths.

## 15. HTTP client: RESTBuilder, REQUEST and DOWNLOAD

Never `require('http')` / `require('https')` and never build a custom client.

| Need | Use |
|---|---|
| A JSON API (send a payload, get a parsed object) | `RESTBuilder` |
| Raw text / HTML / Markdown, custom handling of the status | `REQUEST()` |
| Save a response to a file | `DOWNLOAD()` |

### RESTBuilder

```js
RESTBuilder.GET(url);
RESTBuilder.POST(url, [payload]);
RESTBuilder.PUT(url, [payload]);
RESTBuilder.PATCH(url, [payload]);
RESTBuilder.DELETE(url, [payload]);
RESTBuilder.API(url, action, [payload]);   // a Total.js API endpoint: { schema: action, data: payload }
```

```js
builder.header(name, value);
builder.auth(user_or_token, [password]);
builder.cookie(name, value);
builder.timeout(10000);            // ms, default 5000
builder.urlencoded([payload]);
builder.file(name, filename, [buffer]);
builder.xhr();
builder.keepalive();
builder.insecure();                // skip TLS verification
builder.noparse();                 // return the raw body
builder.callback(function(err, response) { ... });
builder.promise($);                // errors go to $.invalid
builder.stream(callback);
```

```js
var profile = await RESTBuilder.GET('https://api.example.com/v1/profile')
	.header('Authorization', 'Bearer ' + CONF.api_token)
	.promise($);

var id = await RESTBuilder.API('https://other.example.com/api/', 'orders_create', model).header('x-token', CONF.token).promise($);
```

**Don't use `fetch` on the server** — older versions of Node.js don't have it. Total.js has its own client.

### REQUEST

```js
REQUEST({ url: 'https://example.com/file.md', method: 'GET', timeout: 20000 }, function(err, response) {
	// response.status, response.body (string), response.headers
});

// without a callback it returns a Promise
var response = await REQUEST({ url: url });
```

Parallel downloads with a limit (max. 4 at a time) via `Array.wait`:

```js
FILES.wait(function(path, next) {
	REQUEST({ url: SOURCE + path, timeout: 20000 }, function(err, response) {
		if (err || response.status !== 200)
			error = err || new Error(path + ' ' + response.status);
		else
			files[path] = response.body;
		next();
	});
}, function() {
	// all done
}, 4);
```

### DOWNLOAD

Saves the response directly to a file (Promise):

```js
await DOWNLOAD('https://example.com/data/items.json', PATH.tmp('items.json'));
```

Paths: `PATH.databases(name)`, `PATH.public(name)`, `PATH.tmp(name)`.

## 16. Periodic tasks, cron, events and workers

```js
ON('ready + service', function(counter) {
	// Every hour (service counter increments every minute)
	if (!counter || counter % 60 === 0) {
		badges();
		ACTION('Items|refresh').callback(ERROR('Source offline'));
	}
});
```

- `ready` fires once after startup (`counter` is `undefined` then), `service` fires **every minute** with an increasing `counter`.
- `ON('ready + service', …)` = one handler for both events.
- Run time-dependent tasks (e.g. expiring the "NEW" badge) **even when the data source fails** — otherwise stale values stay in place.

### `ON('ready')`

Fires when the app is loaded — a safe place to warm caches or start optional connections. When it is registered after boot, the handler is called immediately.

### `ON('service')` for light maintenance

```js
ON('service', function(counter) {
	if (counter % 5 === 0)
		FUNC.refresh_storage_usage();
	if (counter % 30 === 0)
		FUNC.remove_expired_sessions();
});
```

Good uses: expiring sessions, refreshing counters, light cleanup. Keep it fast.

### `CRON()`

For wall-clock schedules. Standard 5-field cron; the returned object has `.remove()`.

```js
CRON('*/5 * * * *', function() {
	FUNC.run_escalations();
});

CRON('0 3 * * *', async function() {
	await FUNC.purge_tmp_files();
});
```

**Never use `setInterval` job runners or `node-cron`.** `ON('service')` = "every N minutes since start", `CRON()` = "at this time". Both belong in `definitions/jobs.js`.

### A job queue without workers

Most backends do not need workers. A queue table + `CRON()` is enough:

```js
FUNC.process_queue = async function(limit) {
	var jobs = await DATA.find('tbl_job').where('status', 'queued').sort('dtcreated').take(limit || 10).promise();
	for (var i = 0; i < jobs.length; i++) {
		try {
			await FUNC.process_job(jobs[i]);
		} catch (e) {
			Total.error(e, 'job ' + jobs[i].id);
		}
	}
};

CRON('* * * * *', function() {
	FUNC.process_queue(15);
});
```

### Workers

Only for isolated heavy work (image processing, big imports). The code lives in `/workers/<name>.js`:

```js
var worker = NEWTHREAD('resize');        // worker_threads, file: workers/resize.js
var fork = NEWFORK('import');            // child_process.fork
var pool = NEWTHREADPOOL('resize', 4);
```

`NEWTHREAD()` / `NEWFORK()` without a name attach to the parent from inside the worker script.

### Events

```js
ON('orders.create', function(order) { ... });
EMIT('orders.create', order);
```

Use events for decoupled side effects (notify, realtime push, audit). Do not replace actions with an event bus.

## 17. WebSockets

Use the framework's sockets. Do not add `socket.io`.

### Gateway

A socket route is one controller instance shared by all its clients. Messages are **JSON by default**: the handler receives a parsed object and `send()` takes an object (`@text` / `@binary` on the route change that).

```js
// controllers/realtime.js
exports.install = function() {
	ROUTE('+SOCKET /realtime/', socket);    // AUTH() runs at the handshake
};

function socket($) {

	MAIN.ws = $;

	// runs when the last client leaves; drop process-global references here
	$.autodestroy(() => MAIN.ws = null);

	$.on('open', function(client) {
		FUNC.realtime_bind(client, client.user.id);
	});

	$.on('close', function(client) {
		FUNC.realtime_unbind(client);
	});

	$.on('message', function(client, msg) {
		if (msg && msg.type === 'ping')
			client.send({ type: 'pong', ts: NOW });
	});
}
```

| API | Meaning |
|---|---|
| `$.on('open', fn(client))` | a client connected |
| `$.on('close', fn(client, code, reason))` | a client disconnected |
| `$.on('message', fn(client, message))` | a message arrived |
| `$.send(obj, [filter])` | broadcast to all clients of the route |
| `$.autodestroy(fn)` | destroy the route instance when it is empty |
| `client.send(obj)`, `client.close(code, reason)` | one client |
| `client.user`, `client.query`, `client.ip`, `client.headers` | handshake data |

Dynamic socket routes are just more `ROUTE('SOCKET /path/', handler)` entries.

### Authentication by the first message

A browser cannot send custom headers with a WebSocket. When the token is not in a cookie, register the route without `+` and authenticate in the first message:

```js
function socket($) {

	$.on('open', function(client) {
		client.authtimer = setTimeout(() => client.close(4001, 'auth timeout'), 15000);
	});

	$.on('close', function(client) {
		clearTimeout(client.authtimer);
		FUNC.realtime_unbind(client);
	});

	$.on('message', async function(client, msg) {

		if (!msg || !msg.type)
			return;

		if (msg.type === 'auth') {
			var user = await FUNC.realtime_auth(client, msg.token);
			if (user) {
				clearTimeout(client.authtimer);
				client.send({ type: 'auth_ok', userid: user.id });
			} else {
				client.send({ type: 'auth_error' });
				client.close(4003, 'unauthorized');
			}
			return;
		}

		if (!client.userid)
			return;

		// ... authorized messages
	});
}
```

`FUNC.realtime_auth` decrypts the token the same way `AUTH()` does, calls `FUNC.realtime_bind` and returns the user.

### Sending to a user

Keep the connection registry on `MAIN` and the public API on `FUNC` (`definitions/realtime.js`):

```js
MAIN.ws_users = {};     // userid → Set of clients

FUNC.realtime_bind = function(client, userid) {
	if (!MAIN.ws_users[userid])
		MAIN.ws_users[userid] = new Set();
	MAIN.ws_users[userid].add(client);
	client.userid = userid;
};

FUNC.realtime_unbind = function(client) {
	var set = MAIN.ws_users[client.userid];
	if (set) {
		set.delete(client);
		if (!set.size)
			delete MAIN.ws_users[client.userid];
	}
};

FUNC.realtime_send = function(userid, msg) {
	var set = MAIN.ws_users[userid];
	if (set) {
		for (var client of set)
			client.send(msg);
	}
};
```

Actions then push through `FUNC.realtime_send(userid, { type: 'order', id: id })`, usually from an event handler (`ON('orders.create', …)`).

### More instances

The in-process `MAIN.ws_users` does not cross Node processes. With more than one instance, a small Redis pub/sub bridge inside a definition is a legitimate `require('redis')`. Keep the public API as `FUNC.realtime_send`.

`WEBSOCKETCLIENT` exists when the server itself needs an outbound socket.

| Need | Mechanism |
|---|---|
| Pure helper | `FUNC.x = function(...)` |
| Integration | `/modules/x.js` → `MODS.x` |
| Domain operation | `NEWSCHEMA` / `NEWACTION` |
| Boot / auth / db | `definitions/` |
| Request/response sugar where `this` must be `$` | `Total.extend('$', 'x', fn)` |

### `Total.extend()`

Adds a method to a framework prototype:

```js
Total.extend('$', 'mail', function(address, subject) {
	var $ = this;
	return MAIL(address, subject, 'mail/notif', { user: $.user });
});

// later in an action
$.mail(user.email, '@(Welcome)');
```

| First argument | Target |
|---|---|
| `'$'` / `'options'` | the action `$` |
| `'controller'` | HTTP and WebSocket controllers |
| `'error'` / `'errorbuilder'` | `ErrorBuilder` |
| `'restbuilder'` | `RESTBuilder` |
| `'mail'` / `'email'` | mail message |
| `'view'` | view engine |
| `'querybuilder'` / `'database'` | QueryBuilder — verify in the installed version first; prefer a `FUNC` helper that takes a builder |

Use it only when many actions need the same **context** helper. Not for ordinary functions:

```js
// WRONG — not a request concern
Total.extend('$', 'hashPassword', function(pw) { ... });

// RIGHT
FUNC.hash_password = function(pw) {
	return String(pw).sha256(CONF.salt);
};
```

Two or three extensions per app are plenty. Do not invent a utility module of prototype patches.

### `DEF`

Framework defaults; override rarely.

```js
DEF.onSuccess = function(value) {
	return { success: true, value: value };
};
```

Changing `DEF.onSuccess` changes `$.success()` globally. Do not replace it with `{ ok: true, data }` unless the whole product (and every client) agrees.

### `MIDDLEWARE()`

`MIDDLEWARE('name', function($, next) { … })` plus the route flag `#name`. Use it for rare cross-cutting HTTP concerns that `AUTH()` and actions cannot express. Do not rebuild Express middleware chains — auth, permissions and validation already have framework homes.

### Syntax

| Notation | Meaning |
|---|---|
| `@{model.name}` | output **with HTML escaping** |
| `@{!html}` | raw output (no escaping) |
| `@{if cond}…@{else}…@{fi}` | condition |

| `@{section('head')}` | section output (in the layout) |
| `@{body}` | view content in the layout |

Available in views: `model`, `query`, `controller` (`controller.url`), `repository`, `REPO`, `CONF`.

### A layout with a section for `<head>`

`views/layout.html`:

```html

	<meta charset="utf-8" />
	@{section('head')}
	…
</head>
<body>
	<main id="content">
		@{body}
	</main>
</body>
```

```html

```

A comment at the start of a view describes the shape of the model — it helps both people and AI:


## 20. Local methods for views (`repository.func`)

Instead of a global `FUNC.*`, each controller has its own object of methods and passes it to the view. It's clear where a method comes from, and nothing pollutes the global scope.

```js
// Local methods for the views of this controller
// Controller: view.repository.func = Func;
// View: @{repository.func.name()}
const Func = {};

Func.pageurl = function(search, page) { … };
Func.date = function(value, format) { … };
Func.badge = function(m, large) { … };

function browse($) {
	ACTION('Items|browse', input).callback(function(err, response) {
		$.view('browse', response).repository.func = Func;
	});
}
```

In the view:

```html
<a href="@{repository.func.pageurl(query.search, p)}">@{p}</a>
<h3>@{!repository.func.badge(m)}@{m.name}</h3>
```

A function that returns HTML is called via `@{!…}` and **must escape** all of its inputs itself (`.encode()`).

### `Func` vs `FUNC`

They do not compete:

| | Local `Func` | Global `FUNC` |
|---|---|---|
| Purpose | presentation helpers for the views of one controller (URLs, badges, `<head>`) | application helpers shared by features (permissions, sessions, hashing, audit) |
| Declared in | the controller file | `definitions/` |
| Used from | views via `repository.func` | actions, definitions, modules, controllers |

## 22. SEO recipes

All SEO is rendered on the server — crawlers and AI get finished HTML.

### One function for `<head>`

A single controller function, `Func.head($, type, model)`, builds for every page type:

- `<title>` (≤ 60 characters), `meta description` (cut by `shorten()` to 160 characters at word boundaries),
- `meta robots` — `index,follow,max-image-preview:large` / `noindex,follow` for search results,
- `link rel=canonical` (always from `CONF.url`),
- `link rel=prev/next` for pagination,
- Open Graph and Twitter Card,
- JSON-LD.

All values go through `.encode()`, JSON-LD through:

```js
function jsonld(value) {
	return '<script type="application/ld+json">' + JSON.stringify(value).replace(/</g, '\\u003c') + '</script>';
}
```

(`<` is escaped so that text containing `</script>` can't close the script.)

### JSON-LD by page type

| Page | Types |
|---|---|
| homepage | `WebSite` (+ `SearchAction`), `CollectionPage` with `ItemList` |
| pagination | `CollectionPage` |
| detail | a type matching the content (`Article`, `Product`, `SoftwareSourceCode`…), `BreadcrumbList` |
| static page | `TechArticle`, `BreadcrumbList` |

### Rules that proved useful

- **Unique descriptions:** if a description isn't distinctive, prepend the item name (`name + ': ' + description`).
- **One `<h1>`** per page; if a section has no heading, add a hidden `<h2 class="sr">` (no skipped levels).
- **Search results** = `noindex,follow` (not indexed, but links are followed).
- **Invalid parameters** (`?page=99`, `?page=abc`) = a real **404**, not an empty list.
- **Non-canonical URLs** = 301 to the canonical one.
- **Helper URLs** (previews, downloads) = `X-Robots-Tag: noindex` and a link with `rel="nofollow"`.
- **Images** have `width`/`height` and `alt`; the first one gets `fetchpriority="high"`, the rest `loading="lazy"`.

### sitemap.xml and robots.txt generated by code

```js
ROUTE('FILE /sitemap.xml', sitemap);
ROUTE('FILE /robots.txt', robots);

function robots($) {
	$.response.minify = false;
	$.text('User-agent: *\nAllow: /\nDisallow: /download\nDisallow: /admin/\n\nSitemap: ' + hostname($) + '/sitemap.xml\n');
}
```

`Disallow: /download` (without a trailing slash) covers `/download/`, `/download.js` and `/download.css`.

### For AI search engines

- `public/llms.txt` — a short description of the project with links to the documentation,
- `<link rel="alternate" type="text/plain" href="/llms.txt" />` in the layout,
- robots.txt doesn't block AI crawlers, and the content is in the HTML (not only in JS).

## 23. Frontend without a framework

### Live search on top of server-rendered HTML

The server renders results into `<div id="results">`. The script downloads the whole page and swaps only this block — a single source of truth, and it also works without JS (a plain GET form).

```js
var load = function(url) {
	ctrl && ctrl.abort();
	ctrl = new AbortController();
	fetch(url, { signal: ctrl.signal }).then(r => r.text()).then(function(html) {
		var parsed = new DOMParser().parseFromString(html, 'text/html');
		var results = parsed.getElementById('results');
		if (results) {
			doc.getElementById('results').replaceWith(results);
			doc.title = parsed.title;
			history.replaceState(null, '', url);
		}
	});
};
```

160 ms debounce; the `/` key focuses the search field.

### Copy to clipboard (Safari included)

Safari allows an asynchronous clipboard write only via `ClipboardItem` with a Promise (otherwise it loses the "user gesture"):

```js
if (clipboard.write && window.ClipboardItem)
	copy = clipboard.write([new ClipboardItem({ 'text/plain': source().then(t => new Blob([t], { type: 'text/plain' })) })]);
else
	copy = source().then(t => clipboard.writeText(t));
```

The content is downloaded only after the click — the page doesn't carry tens of kB of code for nothing.

### Live preview in an `<iframe>`

```html
<iframe src="/items/my-item/preview/" loading="lazy"
	sandbox="allow-scripts allow-same-origin allow-forms allow-modals allow-popups allow-downloads"></iframe>
```

Useful for showing a runnable HTML example next to its documentation. The server can insert a small `<style>` (e.g. padding) before `</head>` of the embedded HTML. For full isolation serve previews from a different subdomain.

### Mobile menu

A `☰` button with `aria-expanded`/`aria-controls`, a panel under the header, closing via Escape, a click outside, a click on a link, and `matchMedia` when switching to desktop. Links are 48 px tall (touch targets).

### Favicons from the SVG logo

- `favicon.svg` with a style for `prefers-color-scheme: dark`,
- `favicon.ico` (16/32/48), `apple-touch-icon.png` (180, **opaque background** — iOS fills transparency with black), `icon-192/512.png` + `site.webmanifest`,
- rasterized with Pillow using supersampling (draw 16× larger, then `LANCZOS`).

```html
<link rel="icon" href="/favicon.ico" sizes="32x32" />
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<link rel="manifest" href="/site.webmanifest" />
```

### Color contrast

A light accent (`#FF7B00`) on a light background has a contrast of ~2.4 : 1 → introduce a darker token for small text (`--accent-ink: #AD5000`, ≥ 4.5 : 1) and keep the light one for large elements, icons and graphics.

## 24. Performance

- **Compute when data changes, not when rendering.** For example, a "NEW/UPDATED" badge is stored in `m.badge` by the action (after startup, after a refresh, once an hour); the view only renders it.
- **Cache expensive renders** with a key based on the content:

  ```js
  var stamp = isodate(model.updated) + (model.readme || '').length;
  if (cache && cache.stamp === stamp)
  	return cache.html;
  ```

- **Images** from data URIs are written to disk only when their SHA1 checksum changes.
- **Library scripts** in `<head>` get `defer` so they don't block rendering.
- **The list action** returns only the needed properties (`keys`), not whole objects with readme and code.
- **Search:** matches in the name come first, matches in the description follow.

### With a database

- **Filter in the query, never in JavaScript.** Do not load a table to `.filter()` it:

  ```js
  // WRONG
  var all = await DATA.find('tbl_order').promise();
  var mine = all.filter(m => m.userid === id);

  // RIGHT
  var mine = await DATA.find('tbl_order').where('userid', id).where('isremoved', false).promise($);
  ```

- **No N+1 loops.** One `DATA.find().in('id', ids)` instead of a `DATA.read()` per id.
- **Select only what you return:** `.fields('id,name')`, or the field list of `autoquery()`.
- **Lists are always paginated** (`DATA.list` + a max. limit).
- **Denormalized lists** are SQL views (`view_order`), not joins assembled in JavaScript.
- **Cache hot, rarely changing rows** (session snapshots) in `MAIN` / `CACHE`, and invalidate on update.

## 25. Robustness and security

### Atomic swap of downloaded data

Never write a downloaded file directly over production data. Download it aside, validate the format, and only then swap:

```js
await DOWNLOAD(url, tmpfile);

items = (await Total.readfile(tmpfile, 'utf8')).parseJSON(true);

// e.g. an old format of the file would break the whole site
if (!(items instanceof Array) || !items.length || !items.every(m => m && typeof(m) === 'object' && m.name && m.preview)) {
	$.invalid('Invalid format of items.json');
	return;
}

await PROMISIFY(Total.Fs.rename, tmpfile, filename);
```

On an error the site stays on the last valid data.

### Cache with a fallback

Remote content (e.g. documentation pulled from a repository) is loaded at startup from a local copy in `databases/` (available immediately) and only then refreshed from the network. If the network fails, the last version stays.

### More principles

- Every value going into HTML/attributes goes through `.encode()`; HTML returned by functions used in `@{!…}` must be escaped inside the function.
- `X-Robots-Tag` for non-public/helper responses.
- Protect public endpoints that trigger expensive operations (e.g. a manual data refresh) with a token, or remove them.
- Isolate third-party code in previews (sandbox, ideally a different origin).

### Backend security checklist

- **Routes:** everything is `+API` / `+POST` unless it is deliberately public; public writes (login, register, forms) are rate-limited with `BLOCKED()`.
- **Input:** every action declares `input` / `query` / `params`; never read undeclared fields from `$.body`.
- **Identity:** `userid`, roles and permissions come from `$.user`, never from the payload.
- **Ownership:** part of the query (`.where('userid', $.user.id)`), with `.error(404)`.
- **SQL:** QueryBuilder first, parameterized `DATA.query(sql, [args])` only where the builder cannot express the query; no string concatenation.
- **Paths:** generated names on known roots; `PATH.verify()` is not a sanitizer ([section 14](#14-filesystem-path-and-uploads)).
- **Uploads:** a size limit on the route (`<10MB`), an extension whitelist, signed download ids.
- **Output:** `FUNC.user_safe()` strips password hashes, reset tokens and secrets; never return raw rows of `tbl_user`.
- **Passwords:** hashed with a salt from `CONF`; tokens are opaque (`ENCRYPTREQ`).
- **Secrets:** in `config` / `(env)` keys, never in code or in responses.
- **Errors:** user-facing errors are localized messages (`@(…)`); details go to the log (`Total.error(err, 'label')`), not to the client.

## 26. Anti-patterns

The mistakes that agents and newcomers produce most often. Each has a framework-native replacement.

| Don't | Do |
|---|---|
| `require('../modules/storage')`, `require('./lib/…')` | `MODS.storage`, `FUNC.*` |
| `require('fs')`, `require('path')`, `require('crypto')`, `require('https')` | `PATH.*`, `PATH.fs`, `Total.Crypto` / `HASH()`, `RESTBuilder` |
| `require('../config.json')`, a settings/env wrapper, `process.env.X` in feature code | `CONF.x` (+ `(env)` keys) |
| `class UserRepository`, service classes, an ORM, `require('pg')` in actions | `DATA` in actions; views in SQL |
| `function sendOk(res, data)`, `authMiddleware(req, res, next)` | `$.success()`, `$.callback()`, `$.invalid()`, `AUTH()` |
| `$.json({ ok: true, data: item })` or a hand-rolled `{ success: true, value }` | `$.success(item)` / `$.callback(item)` |
| `$.json()` / `$.view()` inside an action | `$.success()` / `$.callback()` — the action `$` is not a controller |
| Decrypting the token again in a handler | `+` route flag and `$.user` |
| Passport, `jsonwebtoken` | `AUTH()` + `ENCRYPTREQ` / `DECRYPTREQ` |
| `setInterval(tick, 300000)`, `node-cron` | `ON('service')`, `CRON()` |
| `socket.io` | `ROUTE('SOCKET …')` |
| `https.request({...})`, `fetch` on the server | `RESTBuilder`, `REQUEST()`, `DOWNLOAD()` |
| `DB()` everywhere (older docs) | `DATA`; `DB()` only for a fresh controller |
| Loading a table and filtering in JS; a `DATA.read` per id in a loop | `.where()`; `.in('id', ids)` |
| `DATA.query('SELECT … WHERE id=$1 LIMIT 1')` followed by `if (!rows.length)` for a plain read, insert, update or delete | `DATA.read('tbl').id(id).error(404)`, `DATA.insert()`, `DATA.modify()`, `DATA.remove()`; `DATA.query()` only for joins, aggregates and expressions ([section 12](#12-postgresql-data-and-querybuilder)) |
| `ROUTE('POST /x/', fn, ['upload'], 1024)` (Total.js 4) | `ROUTE('POST /x/ @upload <1MB', fn)` |
| `CORS()` in every plugin | one `CORS()` in a definition |
| One 2,000-line `definitions/func.js` | several definitions split by concern |
| `Total.extend()` for ordinary helpers | `FUNC` |
| Business records in `MAIN`; sessions in `TEMP` or `REPO` | database; `MAIN` |
| REST-resource controllers with business rules | actions + the `/api/` gateway |
| `src/`, `lib/`, `services/`, `repositories/`, `utils/`, `middleware/` | the framework directories ([section 2](#2-project-structure)) |
| `const` for every local, `forEach` with arrows, spaces, double quotes | `var`, classic `for`, tabs, single quotes ([section 5](#5-coding-style)) |
| Copying another product's tables and schema names | copy the mechanism: plugin + `NEWSCHEMA` + `DATA` + `FUNC` |
| A file without a comment at its top; `// sets the value` above `x = value`; a "magic" number without a reason | A header that says what the file does and needs; comments that say why ([section 5](#5-coding-style), "Comments") |
| A product name, URL, token or limit written into an action; a helper that only works with this project's tables | Values in `config`, dependencies listed at the top, a unit that can be copied ([section 5](#5-coding-style), "Reusable code") |

## 27. Gotchas

| Problem | Solution |
|---|---|
| `$.invalid(404)` / `$.invalidsafe()` returns **JSON** | a custom `notfound($)` with `$.response.status = 404` and a view |
| `@{!section('head')}` in the layout crashes | use `@{section('head')}` |
| `node -e "…Total.run()"` crashes on `process.argv[1]` | always run a file (`node index.js`) |
| `fetch` doesn't exist on the server (older Node.js) | `REQUEST()` / `DOWNLOAD()` |
| `ON('ready')` in a controller didn't fire reliably | `setImmediate(load)` in `exports.install` |
| CSS resets (normalize.css, also bundled in the Total.js UI library `spa.min.css`) give `input[type=search]` `box-sizing: content-box` → the field overflows | `box-sizing: border-box` directly on the input |
| `MEMORIZE().save()` writes only after 10 s | keep it in mind when testing/restarting |
| The Markdown renderer adds `loading="lazy"` and the `hidden` class | don't add it twice, remove `hidden` |
| Images in a readme with `src="URL"` (a syntax example) → 404 | filter out `src` values that aren't addresses |
| Switching the data source to a branch with an old format would break the site | validate before swapping ([section 25](#25-robustness-and-security)) |
| `CONF.url` applies locally too → canonical points to production | intended; when testing, check paths, not the host |
| The action `$` has no `$.json()` / `$.view()` | finish with `$.success()` / `$.callback()` / `$.invalid()` ([section 8](#8-actions-newaction-and-newschema)) |
| `ROUTE(url, fn, ['upload'], size)` silently registers a wrong route | flags and size go into the URL: `@upload <10MB` ([section 9](#9-controllers-and-routing)) |
| `<5m` is a timeout of five minutes, not five megabytes | sizes need the unit `MB` / `kB` |
| `+orders_create` vs `+API` — two different `+` signs | before the method = auth; before the schema string = "has a payload" |
| A module calls `FUNC.x()` at its top level → `undefined` | definitions load after modules; call `FUNC` inside exported functions |
| `TEMP` loses its content every few minutes | runtime state belongs on `MAIN`, expiring values in `CACHE` |
| `PATH.verify()` looks like validation | it only creates the directory; constrain user input yourself |
| `DATA.modify()` / `DATA.remove()` without a filter changes every row | always `.id()` / `.where()` + `.error(404)` |
| `.promise()` without `$` in an action → an unhandled rejection | `.promise($)` in actions; `try/catch` elsewhere |
| A value from `config` arrives as the string `'true'` | declare the type: `allow_register (boolean) : true` |
| WebSocket messages are already parsed JSON | no `JSON.parse` / `JSON.stringify`; send objects |

## 28. Checklist for a new project

**Basics**
- [ ] `index.js` with a `release` switch, locally `node index.js` (debug, port 8000)
- [ ] `config` with `url : https://example.com`
- [ ] `.gitignore` (`index.js.json`, `index.js.map`, `index.pid`, `tmp/`)
- [ ] logic in `actions/`, the controller only calls actions and renders
- [ ] view helpers in a local `Func` + `view.repository.func = Func`; shared helpers on `FUNC`
- [ ] integrations and shared libraries in `modules/` (`MODS.<name>`), never `require()`
- [ ] every file starts with a comment (what it does, what it needs, how to call it); constants and non-obvious decisions say why
- [ ] every action, module and plugin can be copied to another project: project values in `config`, dependencies listed at the top

**Layout and views**
- [ ] `@{section('head')}` in the layout, `@{section head}…@{end}` in views
- [ ] CSS tokens + dark mode, mobile menu, skip link, `lang`
- [ ] HTML 404 via `ROUTE('#404')`
- [ ] a comment with the model shape at the top of every view

**SEO**
- [ ] title, description, canonical, robots, OG, Twitter, JSON-LD on every page
- [ ] one `<h1>`, no skipped heading levels
- [ ] `sitemap.xml`, `robots.txt`, `llms.txt`
- [ ] 301 for non-canonical URLs, 404 for invalid parameters, `noindex` for search
- [ ] favicons (SVG + ICO + apple-touch + manifest)

**Data and operations**
- [ ] downloads via `REQUEST`/`DOWNLOAD`, validation before swapping
- [ ] periodic tasks via `ON('ready + service')`; recalculate time-dependent values even when the source is down
- [ ] after deployment: Google Search Console + Bing Webmaster Tools, submit the sitemap

**API backend**
- [ ] `config`: `database`, `salt`, typed keys; no secrets in code
- [ ] `definitions/db.js` (`querybuilderpg`), `definitions/auth.js` (one `AUTH()`), `definitions/func.js`, one `CORS()`
- [ ] every feature is `plugins/<feature>/index.js` (routes) + `schemas/<feature>.js` (`NEWSCHEMA`)
- [ ] all JSON work goes through `+API /api/`; plain routes only for files, health, webhooks, sockets
- [ ] every action declares `input` / `query` / `params` and ends with `$.success()` / `$.callback()` / `$.invalid()`
- [ ] permissions via `permissions:` / `FUNC.require_perm`; ownership in the query
- [ ] tables `tbl_*` with `id`, `dt*`, `is*`; lists via `DATA.list().autoquery()`
- [ ] uploads: `@upload <size>`, an extension whitelist, `FILESTORAGE` or `MODS.storage`, signed download ids
- [ ] jobs via `CRON()` / `ON('service')`; realtime via `ROUTE('SOCKET …')` + `FUNC.realtime_send`
- [ ] no internal `require()`, no `fs` / `path` / `https` imports, no `setInterval`, no repositories

**New feature (plugin) in an existing backend**
- [ ] SQL: table (+ view for lists) following the naming and field order
- [ ] `plugins/<feature>/schemas/<feature>.js` with `list`, `read`, `create`, `update`, `remove`
- [ ] `plugins/<feature>/index.js` with the routes and `exports.permissions`
- [ ] shared helpers to `FUNC`, integrations to `MODS`, side effects via `EMIT`
